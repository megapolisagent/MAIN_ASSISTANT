## Как читать таблицу

Каждая строка — один найденный дефицит: разрыв между тем, что есть сейчас, и тем, что должно быть, чтобы шаг работал предсказуемо, не «на памяти» Марии. Срочность — три оценки от 1 до 3, перемноженные (макс. 27):
- **Impact** — насколько плохо, если не чинить.
- **Frequency** — как часто узел вообще задействован (на каждой сделке или раз в год).
- **Silence** — узнает ли Мария сама, или только когда клиент уже тихо ушёл.

## Ранжированные дефициты

### 1. Продажи — нет резервного исполнителя на приёме лидов (18 = 3×3×2)

| Поле | Значение |
|---|---|
| Узел | Продажи → приём и обработка входящего лида |
| Тип | нет исполнителя/роли |
| Условие | Лиды сейчас принимает и ведёт только сама Мария; роль «агент первичной квалификации лида» названа как опция, но не подключена. |
| Критерий | Единственная веха ближайшего этапа бизнеса — «лиды стали приходить клиенты» — держится на этом шаге; он должен работать независимо от занятости одного человека. |
| Причина | Резервная роль ещё не нанята/не подключена — направление в целом на старте. |
| Эффект | Лид, пришедший в момент, когда Мария недоступна (болезнь, переговоры, перегрузка), не получает своевременного ответа — в премиум-сегменте, где решает скорость и внимание, это прямая потеря сделки без предупреждения. |
| Рекомендация | Подключить хотя бы минимальную резервную роль (агент первичной квалификации или чёткий протокол «кто подхватывает лид, если Мария недоступна 4+ часов») раньше, чем расти в объёме лидов. |

### 2. Продвижение — контент-план есть, публикация не идёт (18 = 3×2×3)

| Поле | Значение |
|---|---|
| Узел | Продвижение → регулярная публикация по 7-дневному контент-фреймворку |
| Тип | обрыв процесса |
| Условие | Контент-фреймворк (материал на 7 архетипов по дням недели) уже существует как готовый актив. Исполнитель («агент-контент-стратег») не подключён, календарь публикаций не собран, метрика публикаций даже не подтверждена владельцем. |
| Критерий | Направление существует именно для того, чтобы кормить воронку лидов через контент — процесс должен идти непрерывно, а не разово. |
| Причина | Готовый материал не переведён из документа в операционный процесс — нет ни исполнителя, ни календаря. |
| Эффект | Стратегическая цель «запустить публичный слой» (обслуживает финансовую цель через контент → доверие → лиды) фактически стоит на месте, при этом выглядит как «материал уже есть» — легко не заметить, что процесс не запущен. |
| Рекомендация | Не собирать новый контент — взять уже готовый фреймворк и назначить конкретного исполнителя публикации с минимальным еженедельным ритмом, прежде чем добавлять что-то ещё в это направление. |

### 3. ИИ-инструмент — клиентский текст не сверяется с голосом бренда (TOV) (18 = 2×3×3)

| Поле | Значение |
|---|---|
| Узел | ИИ-инструмент (property-analyst) → PDF-отчёт клиенту → текстовый блок |
| Тип | нет документа/регламента (в сочетании с бренд-сверкой) |
| Условие | Перед выдачей клиенту текст обязательно проходит через общий skill «Humanizer» (делает текст живым, не роботизированным). Готовый документ голоса бренда — TOV Марии Боголюбовой — существует как актив, но нигде в архитектуре инструмента не подключён как источник для генерации клиентского текста. |
| Критерий | Отчёт продавцу/покупателю в премиум-сегменте — прямая точка контакта клиента с брендом; он должен звучать в узнаваемом голосе Марии (образование, честность, тихая уверенность, без слов вроде «элитный»/«эксклюзивный»), а не просто «человечно» в общем смысле. |
| Причина | TOV существует отдельно как несобранный в систему актив — никто не подключил его к конкретному техническому процессу, который реально пишет клиенту текст. |
| Эффект | Клиент получает грамотный, но потенциально нейтральный текст — тихое размытие бренда именно там, где клиент реально читает документ от агентства; никто не пожалуется на «неправильный тон», просто бренд станет чуть менее узнаваемым со временем. |
| Рекомендация | Добавить TOV-документ как явный источник (не общий Humanizer) для генерации любого клиентского текста в property-analyst — это малое дополнение к уже существующей архитектуре, не новая разработка. |

### 4. Продажи — нет стандарта скорости ответа на лид (12 = 2×3×2)

| Поле | Значение |
|---|---|
| Узел | Продажи → первый ответ на лид |
| Тип | нет документа/регламента |
| Условие | «Скорость первого ответа» упомянута только как предложенная метрика для отслеживания, не как зафиксированный стандарт (например, «ответ за 1 час»). |
| Критерий | Раз это явно названо сигналом успеха направления, должен быть минимальный зафиксированный ориентир, а не только метрика для наблюдения постфактум. |
| Причина | Направление ещё не операционализировано дальше уровня «задача + предложенная метрика». |
| Эффект | Скорость ответа зависит целиком от текущей загрузки Марии в моменте, без явного порога — качество обслуживания лида непредсказуемо даже для неё самой. |
| Рекомендация | Зафиксировать простой ориентир (например, «ответ в течение рабочего дня») — это займёт одну фразу, а не проект. |

### 5. Маркетинг — проверка позиционирования не запущена (6 = 2×1×3)

| Поле | Значение |
|---|---|
| Узел | Маркетинг → проверка позиционирования реальным откликом |
| Тип | обрыв процесса |
| Условие | Задача названа («проверить, не строить заново»), роль-исполнитель («агент-исследователь спроса») не подключена, предложенная метрика («число предметных обращений в неделю») не подтверждена владельцем. |
| Критерий | Позиционирование бизнеса и ИИ-инструмента явно названо непроверенной гипотезой владельца — без цикла проверки оно так и останется гипотезой неопределённо долго. |
| Причина | Направление ждёт своей очереди — приоритет сейчас явно ниже, чем «Продажи» и «Продвижение» (это видно из структуры этапа). |
| Эффект | Стратегия строится на непроверенном предположении дольше, чем нужно — цена ошибки растёт медленно и незаметно, не разово. |
| Рекомендация | Не требует немедленных ресурсов — достаточно подтвердить предложенную метрику как рабочий сигнал и начать её просто считать, даже без отдельного агента. |

### 6. ИИ-инструмент — доставка и проверка отчёта держатся на одном человеке (2 = 1×2×1)

| Поле | Значение |
|---|---|
| Узел | ИИ-инструмент → выдача PDF клиенту + разбор обратной связи |
| Тип | нет исполнителя/роли |
| Условие | Автодоставка клиенту и резервная проверка качества сознательно не входят в Stage 1 — «Мария отправляет руками», она же одна разбирает feedback card. |
| Критерий | На нынешнем малом объёме (Stage 1, прототип) единственная точка допустима как временное решение. |
| Причина | Осознанное архитектурное решение, а не забытый узел — прямо зафиксировано в документации проекта как то, что «не гарантируется на Stage 1». |
| Эффект | Пока объём мал — эффект минимальный. При росте числа отчётов в неделю это станет узким местом первым. |
| Рекомендация | Не трогать сейчас — держать в поле зрения как известный порог: когда отчётов станет больше, чем можно отправлять руками, вернуться к этому узлу первым. |

## Узлы без ранжирования — недостаточно данных для оценки

Ниже — не дефициты, а честно непокрытые материалом узлы. Дописывать сюда дефицит из предположения — запрещено правилом задачи.

- **Юридическое сопровождение сделок** — известна только формула «юрист, вызов на конкретную сделку» и качественный критерий «0 инцидентов». Нет данных о шагах процесса, есть ли уже юрист-партнёр, есть ли договор с ним. Недостаточно материала, чтобы назвать конкретный дефицит, а не предположить его.
- **Финансы/Операционка (документы)** — источник сам называет это открытым вопросом: не выяснено, работает ли Мария как самостоятельный риелтор или под компанией; от этого зависит, какие документы (договор с клиентом и т.д.) вообще применимы. Оценивать «нет документа» без ответа на этот вопрос — значит гадать.
- **Спорная ответственность (4-й тип дефицита)** — не найдено ни одного случая в доступном материале, где две дорожки одновременно активны на одном шаге без ясного владельца. Есть один слабый, не подтверждённый кандидат — возможное пересечение рыночной аналитики между направлением «Маркетинг» и слоем «рынок и аналоги» в ИИ-инструменте — но материала недостаточно, чтобы утверждать конфликт, а не просто два независимых применения похожего анализа.
